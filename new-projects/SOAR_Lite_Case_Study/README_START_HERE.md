# SOAR Lite portfolio case study — delivery package

## What is included

- **SOAR_LITE_CASE_STUDY.md** — complete case-study narrative, requirements matrix, implementation phases, technical challenges, 12 Mermaid diagrams, testing, local deployment, trade-offs, lessons, and limitations.
- **SOAR_LITE_CASE_STUDY_ASSETS.md** — real screenshot shot list, proposed captions/alt text, media safety guidelines, and placement recommendations.
- **SOAR_LITE_CASE_STUDY_EVIDENCE.md** — claim-to-source traceability, verification categories, and limitations on unconfirmed test results.
- **diagrams/*.mmd** — individually editable Mermaid diagrams extracted from the case study.

## Integrating into your portfolio

1. Open the main case study and reuse its narrative under your existing SOAR Lite project route.
2. Render the inline Mermaid diagrams through your portfolio's Mermaid support, or convert the `.mmd` sources to SVG using a trusted Mermaid CLI in your own build environment.
3. Capture **real**, reviewed screenshots in the running local app and replace the indicated placeholders. Do not use generated visuals as proof of functionality.
4. Link code references back to the GitHub repo, and keep the technical deep dive navigable with a contents menu.
5. Keep the distinctions between **real AbuseIPDB enrichment**, **simulated lab containment**, and **manual versus automated verification** intact.

## What was and was not done

The connected public repository and historical development log were inspected and used as the primary evidence. The final full PostgreSQL-suite result has not been independently confirmed. Mermaid source diagrams have been extracted and checked for basic structure; they have **not** been rendered in the target portfolio application. The actual portfolio repository was not provided, so **no portfolio UI code was modified**. Screenshots were not fabricated.
